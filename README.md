## Case study summary

The database stores the academic records of students in XYZ University. Each student belongs to a department, is assigned to a level, and registers for courses during a specific semester and academic year. Each lecturer belongs to a department and teaches one or more courses. The system records department details, course details, lecturer-course assignments, and final academic performance.

This design supports the required portfolio tasks: modelling the data, validating data integrity, querying academic records, testing transaction behaviour, and discussing alternative NoSQL and distributed database strategies.
